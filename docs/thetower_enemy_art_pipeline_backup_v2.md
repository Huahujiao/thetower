## 1. 文档目的

这份文档用于整理当前《黑塔 / TheTower》敌人物美术生成相关的完整上下文，包括：

- 美术风格目标
- 形式选择与技术判断
- 贴图生成的统一要求
- 当前已经验证过的示例结果
- 后续批量生产流程

本文件用于备份，后续可直接作为继续生成 30+ 敌人物素材时的参考基准。

## 2. 当前核心结论

### 2.1 最终内容呈现形式

最终采用：

**3D 棋盘 / 场景 + 2D 纸偶式敌人部件 + 全局旧纸/印刷风格后处理**

不采用：

- 纯低模 3D 角色
- 纯 2D 逐帧动画
- 完全真实皮影风

### 2.2 角色技术路线

敌人继续使用当前思路：

- 每个敌人由多个 2D 部件组成
- 部件可用于骨骼/拼装动画
- 部件贴图为透明 PNG
- 敌人在场景中以“立在棋盘上的纸偶/皮影偶”形式出现

### 2.3 风格方向

目标不是普通暗黑幻想概念图，也不是传统纯黑皮影，而是：

> **中国妖异旧书 / 志怪图鉴 / 纸戏台 / 旧版印刷纸偶**

可以概括为：

> **一本会动的中国妖异旧书，里面搭着一个立体纸戏台。**

## 3. 风格目标（Style Bible）

### 3.1 核心风格关键词

- 中国妖异
- 旧书 / 志怪图鉴
- 纸偶 / 纸戏台
- 旧版印刷感
- 大色块
- 墨线轮廓
- 少量手工颜料不均匀感
- 少量旧漆、骨、铜、苔藓、腐木等材质感
- 平面化，不追求真实立体光照
- 强轮廓、少噪点、适合缩小后阅读

### 3.2 视觉上要保留的特征

- 角色有明确且夸张的外轮廓
- 内部结构可有少量纹样与装饰，但必须克制
- 颜色以 2～3 段明暗为主，避免连续柔滑渐变
- 局部允许少量亮点色，用于识别敌人类型
- 材质可有：骨、旧布、铜、苔藓、根须、漆面、陶裂等
- 应保留一点“剪下来的纸偶部件”的感觉

### 3.3 视觉上要避免的特征

- 普通暗黑幻想概念图感
- 真实 PBR 材质
- 强烈高光
- 金属倒角感
- 过细的装饰与花纹
- 过多裂纹/噪点/无意义小细节
- 类似卡牌立绘的“精修角色插画感”
- 普通游戏式炫光特效感过强的发光眼/发光边

### 3.4 细节密度要求

原则：

- 普通怪：细节较少，偏简洁，突出轮廓
- 精英怪：略多一点装饰和层次
- Boss：允许更复杂，但仍遵守“大轮廓优先于表面细节”

## 4. 旧纸感的分工：原始贴图 vs Three.js 后处理

这是目前已经确认过的关键原则。

### 4.1 原始贴图负责什么

原始贴图本身应包含：

- 纸偶化造型
- 平面化明暗
- 墨线轮廓
- 轻微的手工颜料不均匀感
- 少量材质特征（骨、铜、旧布、苔藓等）
- 轻微旧感，但不能过脏

原始贴图**不应**承担：

- 大面积黄纸底色
- 强烈全图纸纤维
- 大量统一脏污颗粒
- 过重的旧纸滤镜

### 4.2 Three.js 后处理负责什么

全局后处理负责补足统一媒介感，重点包括：

1. 和纸/旧纸纤维感（全屏）
2. 轻微色阶压缩
3. 轻微墨线/边缘强化
4. 极轻微印刷错版/套色错位
5. 暗部颗粒与局部不均匀褪色
6. 统一整体画面气质

### 4.3 最终分工原则

- **原始贴图决定 70% 风格**
- **Three.js 后处理负责剩余 30% 的统一感**

不能期待 Three.js 后处理把一张普通暗黑概念图直接变成旧书纸偶风格。

## 5. 敌人部件图的统一生成要求

这部分综合了现有提示词文件与后续讨论。

参考源文件：

- `/mnt/data/enemy-part-image-prompts.md`

### 5.1 输出形式

每个敌人生成：

- 一张或若干张透明背景 PNG 部件图
- 每张图中包含该敌人的主要部件
- 每个部件分离，便于裁切
- 用于后续自动拆件与命名

### 5.2 统一规范

- 透明背景 PNG
- 正面/近正面视角
- 无透视夸张
- 纸偶/平面风格
- 各部件互不重叠
- 各部件之间留足透明安全间距
- 尽量规整排布，便于自动切图
- 重要部件完整，不可被其它装饰跨越遮挡
- 关节搭接区域要留余量，避免动画时露缝

### 5.3 关于部件排布的补充要求

后续生图时应进一步强调：

- 各部件之间至少保留明确透明间距
- 不为了“好看”做艺术化拼版，而优先考虑“生产可切割性”
- 装饰、流苏、尖角、根须等不得跨入其他部件区域
- 一张图可以像“无边框隐形网格”一样排布

### 5.4 关于部件切割的认识

不要求每个部件本身是矩形。

最终每个部件仍然导出为矩形 PNG，但矩形内部大部分可为透明。

真正关键的是：

- 部件之间不要粘连
- 一个语义部件不要被拆成太多不相连小岛
- AI 输出的部件数量和代码所需 `part.id` 结构应尽量接近

## 7. 批量生产策略

### 7.1 不直接一口气生成 33 只

原因：

- 风格容易逐渐漂移
- 某些体型可能与样板不一致
- 自动切图流程需要先验证
- 先做样板族群更稳妥

### 7.2 推荐按“族群”分批生成

建议分组：

1. **类人 / 人形异怪**
2. **四足 / 兽类**
3. **虫类 / 甲壳类**
4. **植物 / 根系类**
5. **悬浮 / 灯灵 / 灵体类**

每批 4～6 只。

### 7.3 当前最优推进方式

第一阶段：

- 猩鬼风格定标
- 再验证甲虫 / 植物 / 灵体三类

第二阶段：

- 以猩鬼为总基准，按族群继续批量生成

## 8. 自动拆件与导入流程

### 8.1 不能完全依赖人工 Photoshop 抠图

后续敌人数量多、部件多，必须准备自动化工具。

### 8.2 拆件推荐流程

1. 读取透明 PNG
2. 基于 alpha 通道做连通域检测
3. 找到每个独立不透明区域
4. 过滤太小的噪点
5. 计算 bounding box
6. 外扩少量 padding
7. 自动裁切为单独 PNG
8. 人工映射到代码中的 `part.id`
9. 对缺失/粘连/错误部件单独补生成
10. 自动导出最终命名资源

### 8.3 为什么可行

当前这批图已经证明：

- 背景是真透明
- 部件大多是独立透明岛
- 可以通过脚本切出单独区域

### 8.4 后续建议做一个小工具

功能可以很简单：

- 左边显示整张部件图
- 自动识别并框选连通块
- 右侧列出所有切块预览
- 人工为每块指定 `part.id`
- 一键导出为项目需要的命名格式

### 8.5 对应代码命名来源

最终命名应以项目代码中的部件定义为准，重点参考：

- `shadow-enemies.js`
- `shadow-enemy-roster.js`
- `shadow-enemy-variants.js`

## 9. 生成与生产的关系

AI 生成阶段不要强求一次输出就是最终生产图。

更合理的关系是：

- **AI：负责画素材与风格统一**
- **脚本：负责切分、规范化、导出**
- **人工：负责审核结构、映射 part.id、补缺失部件**

复杂敌人的生成策略：

1. 优先尝试整张图集
2. 不理想时拆成 2～3 张图集
3. 仍有问题时，单独生成某些关键部件

## 10. 当前已经明确的下一阶段生产原则

### 10.1 优先级最高

- 继续用猩鬼作为总体视觉母版
- 后续所有敌人要向猩鬼当前最终版靠拢

### 10.2 新怪物生成时必须遵守

- 细节量不要超过猩鬼最终版
- 平面化程度至少与猩鬼一致
- 外轮廓要强
- 不要重新滑回暗黑概念插画风
- 不要过度真实材质
- 不要过度装饰
- 要优先考虑缩小到游戏尺寸后的可读性

### 10.3 不同族群的偏重点

#### 类人 / 骨骼 / 布偶型

- 保持强轮廓
- 允许适量红布、铜饰、骨件

#### 甲虫 / 甲壳型

- 强调壳体结构
- 纹样克制
- 铜甲/纸甲感重于真实机械感

#### 植物 / 根系型

- 叶片与根须要清楚
- 避免细碎过多
- 形体重于表面花纹

#### 灵体 / 灯灵型

- 仍需保持纸偶语言
- 不要变成普通发光幽灵特效
- 发光区域必须克制

## 11. 当前推荐的实际执行顺序

### 阶段 A：风格样板确认

已基本完成：

- 猩鬼样板已接近定稿
- 甲虫、植物方向已初步验证

### 阶段 B：批量生成准备

待执行：

1. 将这份方案固定下来
2. 确认第二只/第三只样板是否也达到可量产标准
3. 建立自动拆件脚本或小工具

### 阶段 C：批量生成

建议顺序：

1. 人形/类人敌人一批
2. 虫类一批
3. 植物类一批
4. 灵体类一批

### 阶段 D：导入项目验证

每批次都要做：

- 自动切图
- 命名映射
- 放回当前动画系统
- 验证待机 / 移动 / 攻击 / 受击 / 死亡
- 检查缩小显示后的可读性
- 再看是否需要微调风格

## 12. 需要持续记住的总原则

1. **不要为了单张图好看，破坏量产一致性。**
2. **不要把复杂纹样当成风格本身。** 风格的核心是轮廓、色块、平面化和媒介感。
3. **普通怪必须优先考虑游戏阅读性。**
4. **纸偶感比写实感重要。**
5. **Three.js 后处理是统一器，不是救世主。**
6. **生成图是素材，不一定是最终资源。** 最终资源需要拆件、规范化、导入验证。

## 13. 当前备份结论（简版）

一句话总结当前路线：

> 《黑塔》的敌人物应继续采用“3D 棋盘 + 2D 纸偶部件”的形式，视觉上走“中国妖异旧书 / 纸戏台 / 志怪图鉴”的方向；原始贴图负责平面化纸偶语言，Three.js 负责统一旧纸印刷感；猩鬼最新版本已经接近可作为 style bible，后续以其为基准分批生成并配合自动拆件工具导入项目。
