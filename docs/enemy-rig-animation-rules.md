# 敌人骨架与动作设计规则

更新日期：2026-09-29。后续 session 开始敌人设计、动画、贴图或编辑器修改前，先阅读本文件。

## 1. 已确认的设计方向

- 采用 **三维空间中的平面纸片骨骼动画**：关节有 X/Y/Z 坐标，部件可以在空间中旋转，但部件本身没有厚度。
- **有 Z 轴不等于有厚度。** Z 用于安排前后关系、关节位置和动作轨迹。不得将部件挤出成实体、加侧壁或倒角来代替空间设计。
- 当前部件全部为零厚度几何纸片，`depth = 0`。侧面看纸片变窄乃至成为一条线是正常现象。
- 工作顺序：敌人结构规划 → 关节骨架 → 几何纸片部件 → 动作 → `/animeedit` 审查 → 用户确认后再制作贴图。
- 首批三个样本为猩鬼 `gnawer`、烬翅蛾 `emberwing-moth`、腐根芽 `rootrot-bud`。2026-09-29 用户明确要求继续按游戏敌人列表设计；目前 33 种敌人都有纸片骨架、几何部件和五种动作。贴图仍须另行审查。

## 2. 坐标与默认朝向

| 项目 | 约定 |
| --- | --- |
| +X | 正面观察时朝画面右侧 |
| +Y | 朝上 |
| +Z | 朝外，即朝正面观察者 |
| 默认正面 | 角色局部朝向 +Z |
| 展示姿态 | 从正面向观察者左侧偏转 30°，即角色自身向右偏 |
| 当前实现 | 根关节静态 `rotationY = -30`，旋转字段使用角度 |

游戏 Three.js 世界原本就是 Y 向上。旧动画编辑器曾沿用 Canvas 的 Y 向下习惯；现在编辑器、数据与游戏投影已统一。仅最终屏幕绘制转换为屏幕 Y 向下，不得因此反转模型数据或相机 up。

三维旋转视图中的轴显示随观察角度变化；“Z 朝外”指正面基准视角，不是要求转动相机后 Z 箭头仍固定朝屏幕外。

### 数据迁移注意事项

- 当前项目格式版本为 5，敌人模板包版本为 9；两者职责不同，后续以代码常量为准。
- 旧 Y 向下数据的迁移包含关节、部件的 `y / rotationX / rotationZ`，以及关键帧的 `dy / rotationX / rotationZ` 取反。Y 迁移不反转 `z / rotationY`；更早版本另有 Z 迁移。
- 迁移必须按版本执行且幂等，不能每次加载再次翻转。
- 首批三个敌人的构建函数仍保留旧屏幕坐标草稿，工厂调用一次 `reflectShadowProjectY` 转到新约定。新增敌人直接使用 Y 向上数据，不得再次反转。
- 模板包版本现为 9；从纸片版 7 或 8 升级时，后续 30 种敌人改用各自的骨架变体。若旧项目有手调改动，先保留一份不关联游戏敌人 ID 的“旧版备份”，再启用新模板；当前选择保持不变。更早的三个旧样本仍一次性迁移到纸片版，以移除已否定的图集切块。

## 3. 先规划敌人由什么组成

每只敌人先明确轮廓、运动方式、攻击器官、承重或悬浮方式，再列出部件表。至少记录：

| 字段 | 应写清的内容 |
| --- | --- |
| 部件 ID / 名称 | 稳定且有解剖或机械含义 |
| 所属关节或骨骼 | 哪个节点带动它 |
| 形状与尺寸 | 纸片轮廓、长宽，不是实体厚度 |
| 枢轴与连接点 | 在哪里转动，如何与相邻部件搭接 |
| 空间位置 | 局部 X/Y/Z、纸片倾角、前后关系 |
| 动作职责 | 哪些动作需要它主动运动或跟随 |

分件应对应有意义的活动结构。上臂、前臂、手爪；内翅、外翅；下茎、上茎、花瓣等可独立运动。脸部标记等装饰应贴近所属纸片并跟随它，不能漂浮在很远的 Z 位置。

**禁止先生成整张敌人图，再从没有结构意义的位置切成两半，最后用整体缩放、摇晃冒充骨骼动作。**

## 4. 关节层级和纸片空间布局

- 根节点承载整体位置、重心及展示朝向；子关节承担局部活动。
- 关节坐标按现有求值器的父子关系理解，避免把世界坐标直接填入子关节局部位置。
- 铰链放在真实连接处；长肢体需要中间关节，不能仅转动整条肢体。
- 部件通过 `attachment` 绑定关节或骨骼。需要随骨转动时使用 `followRotation`，骨绑定位置由 `t` 控制。
- `pivotX / pivotY` 仍是图像式归一化枢轴，左上为原点；渲染几何已处理 Y 向上。不要混淆枢轴约定和世界坐标。
- 左右肢体、翅、花瓣和前后器官必须有合理 Z 层次，不能把所有关节放在同一平面后仅旋转根节点。
- Z 差异必须服务于结构，不能为满足数值跨度随意推远部件。连接处要搭接，避免脱节。
- 翅膀、叶片、花瓣可绕 X/Y 轴倾斜形成空间扇面；它们仍是零厚度纸片。
- 装饰纸片应与底片保持一致的姿态，仅留必要的小偏移避免闪烁。底片旋转时装饰必须继续贴合。
- `layer` 处理绘制顺序，不替代真实 Z 位置。检查编辑器和游戏中的遮挡表现是否一致。

## 5. 敌人结构重点

| 敌人 | 主要关节链 | 动作特征 |
| --- | --- | --- |
| 猩鬼 | 胸椎—颈—头—下颌；骨盆—髋—膝—踝；肩—肘—腕—爪 | 重心起伏、交替迈步、手臂蓄力与挥击、下颌和头部跟随 |
| 烬翅蛾 | 胸部—头/腹/尾；翅根—翅肘—翅尖；触角与足 | 内外翅分段扑动，腹尾滞后，攻击有收翅与展开过程 |
| 腐根芽 | 根球—下茎—上茎—花芽；根、花瓣、刺、叶分支 | 茎段弯曲传递、花瓣开合、刺的攻击、根部支撑 |

这些是设计重点，不要求为每一处装饰添加无用关节，也不要求不同敌人拥有相同数量的部件。

其余 30 种敌人在 `src/animation/shadow-enemy-roster.js` 中先按运动机制建立草架，所有 ID 与 `src/game/data/enemies.js` 中的游戏目录一一对应。草架包含人形、四足、节肢、悬浮体、植株、鸟和群体等起点，但最终结构必须逐只改造。武器、盾、炮管、弹舌、孢囊等专属器官按敌人 ID 装配并参与动作。蟇类使用短肢和宽腹，避免借用犬类轮廓。

`src/animation/shadow-enemy-variants.js` 为这 30 种敌人逐只改造承重结构、关节分支和主动器官。它们的根关节子树拓扑互不相同；新增器官在五种动作中都独立运动。棺门怪以棺根支撑，活弩怪改为三脚弩台，墓碑怪有残足与行根，炉虫与巢母也失去一对原始足。视觉主题还包括寄生树、巡铃、赤轮、潮祀悬裾及自爆灯芯。几何仍是零厚度纸片，异形感来自铰链和空间排布，不靠挤出厚度或贴图。静止姿态接触图见 `docs/enemy-variant-review-v9.png`。

逐只结构与攻击职责见 `docs/enemy-variant-designs.md`。

四足和节肢敌人的头尾轴沿局部 Z：头在 +Z，臀或腹在 -Z。根关节保持 `rotationY = -30` 后，正面观察时头位于画面左侧。蜘蛛的头、胸、腹沿 Z 轴低伏排列，腿先向两侧展开再落地；伏巢蜘蛛有四对腿。不能再把头沿 +X 放置，或把蜘蛛头和腹沿 Y 轴上下堆叠。

## 6. 动作规则

必须包含 `idle / move / attack / hit / death` 五种动作。

| 动作 | 设计要求 |
| --- | --- |
| idle | 有生命感的局部运动，首尾连续；不能只有整只角色缩放 |
| move | 展现行走、飞行或根茎移动机制，肢体有相位差；循环连接自然 |
| attack | 清晰的蓄力、出击、收回；攻击器官轨迹可读，身体重心配合 |
| hit | 冲击方向明确，局部与躯干响应有先后，随后恢复 |
| death | 结构逐步失去支撑并落定，终态稳定，不循环跳回站立 |

- 主要靠关节旋转与合理位移产生动作，根节点整体摇动只能辅助。
- 动作按父子链传递，避免末端与主体完全同步导致僵硬；必要时加入短暂滞后。
- 根据运动需要使用 `dz / rotationX / rotationY`，不能全部退化为屏幕平面的旋转；也不要给每个节点机械添加 Z 摆动。
- 运动中保持连接，避免肢体拉断、关节穿插、装饰脱离或大幅无意缩放。
- 接地角色注意脚底支撑和重心，飞行角色注意翅与躯干配合。
- 在静止姿态、蓄力、最大伸展、回收和死亡终态检查遮挡，不能只看一张 idle 截图。
- 关键帧字段按现有求值器的偏移语义使用；时间单位和插值沿用项目实现，不另建不兼容格式。

## 7. 后续贴图规则

只有用户审查骨架、纸片部件及动作后，才进入贴图阶段。

- 根据已确定的部件表逐部件设计贴图，尺寸、枢轴和连接边缘匹配现有纸片。
- 保持同一敌人的风格、比例和光照一致，保留活动接缝所需的搭接区域。
- 图集裁剪必须明确每个部件的边界和透明留白，逐块检查；不能露出相邻敌人的头或其他素材。
- 贴图替换几何占位外观，不应迫使骨架适应一张错误切割的整图。
- 不得重新启用之前任意切块的旧素材作为已通过审查的方案。

## 8. 实施与验收

主要入口：

- `src/animation/shadow-enemies.js`：首批三个敌人的骨架、部件、动作和所有敌人的模板安装。
- `src/animation/shadow-enemy-roster.js`：其余 30 种敌人的纸片骨架、部件与动作。
- `src/animation/shadow-enemy-variants.js`：其余 30 种敌人逐只不同的活动器官与轮廓变体。
- `src/animation/shadow-rig.js`：数据规范化、版本迁移、骨架求值。
- `src/animation/shadow-geometry.js`：部件几何；这些敌人必须走零厚度平面分支。
- `src/animation/shadow-projection.js`：游戏纸片投影与深度排序。
- `src/ui/AnimeEditor.vue`、`src/ui/ShadowPuppetStage.vue`：编辑器和三维预览。
- `src/render/enemy-puppet.js`：游戏敌人动画绘制。
- `scripts/shadow-rig-check.mjs`：坐标、迁移、骨架和纸片约束检查。
- `scripts/preview-enemy-puppet.mjs`：离线预览，可指定动作、时间比例、视角。

验收清单：

- [ ] 正面基准下 Y 朝上、Z 朝外，默认向画面左侧偏 30°。
- [ ] 所有敌人部件 `depth = 0`，没有挤出侧面；关节和纸片仍有合理空间层次。
- [ ] 三维绕看可解释各部件的连接，正面和游戏大小下轮廓清楚。
- [ ] 五种动作逐一播放，循环连接与非循环终态正确。
- [ ] 装饰跟随底片，连接不脱开，遮挡没有明显跳变。
- [ ] 编辑器与游戏表现一致，已有数据加载后不会重复迁移。
- [ ] 修改代码后运行 `npm.cmd run check:animation`、`npm.cmd run lint`、`npm.cmd run build -- --logLevel error`。
- [ ] 如无法实际打开浏览器验收，应明确说明；离线图和自动检查不能冒充页面验收。

### 历史预览警示

`docs/enemy-volume-review.png` 是已被用户否定的“带厚度”中间版本；`docs/enemy-geometry-review.png` 也是较早版本。**两张图均不能作为当前纸片方案的设计标准或最新验收证据。** 需要预览时，应从当前代码重新生成并注明版本。

## 9. 后续 session 的执行顺序

1. 阅读本文件和用户最新指示，检查当前实现及已保存的数据版本。
2. 明确本次调整哪个敌人、部件或动作，沿用已确认的纸片方案。
3. 先完成结构和动作，再在 `/animeedit` 提供可审查结果。
4. 汇报实际修改、验证结果和未验收项；用户新的明确要求优先于本文件。
