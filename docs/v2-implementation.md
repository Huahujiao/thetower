# V2 重构实施记录

本文件记录 `new_design.md` 已确认并已落地的第一批架构决策。V2 不兼容旧存档和旧规则。

## 入口与备份

- 默认入口仍为 `src/main.js`，现在直接启动 V2。
- 原有 `data`、`game`、`render`、`ui`、入口和样式已移至 `src/legacy/`。
- `legacy` 不参与默认构建；新代码不得在运行时导入它，只可作为人工查阅和局部复用的参考。

## 当前模型

- `GameRun`：整局状态、玩家、回合、动作、存档和事件通知。
- `Dungeon`：房间与门连接图；第一版为无岔路的线性图。
- `Room`：独立持有棋盘、翻开状态和实体。只有当前房间参与回合，离开后的房间完全冻结。
- `Tile`：空间位置，保存翻开状态和实体占位。
- 实体：敌人、物品、金币、门和开门机关。玩家的位置属于 `GameRun`，不与其他实体重叠。

## 地图配置

第一版房间数量为 `1 / 3 / 4 / 3 / 1`，共 12 间；中间三层拥有多房间，但所有房间构成一条可往返的主路径。

- 第一层唯一房间：8×8。
- 其他房间：8 行，列数随机为 8 到 12。
- 每个相邻房间由一对双向门连接。
- 锁门的机关在来源房间内；拾取后立即永久解锁该连接，不占用背包。
- 门和到达格初始隐藏。从门进入未探索房间时，只自动翻开到达格并让玩家站上去。

## 行动与回合

- 玩家八方向寻路，只能穿过已翻开的空格；物品、敌人、门均阻挡路径。
- 翻开隐藏格前，角色会先走到可达的相邻空格；翻开后不自动踏入目标格。
- 武器射程暂按曼哈顿距离计算。
- 一次移动和交互为一个回合；药剂和 buff 暂不耗回合，换装备和磨刀石耗回合，整理与丢弃不耗回合。
- 进门会推进回合计时，但不让离开房间或到达房间的敌人免费行动。
- 敌人按翻开顺序行动。基础实现包含静止近战/远程、攻击距离与冷却。
- 穿过敌人射程再离开时，敌人会以半伤优先攻击，并有 30% 概率使玩家停在途中。

## 数值与内容边界

- 理智、污染、旧钥匙碎片、旧层间休整和 7 层出口已从 V2 移除。
- 背包为 4 行×6 列；武器耐久只保存剩余次数，剩 1 次时攻击减半，用尽即销毁。
- 当前内容用于验证系统：基础武器、药剂、一次性伤害 buff、磨刀石、金币、锁门机关、近战/远程/重甲敌人与最终 Boss。
- 圣遗物的旧效果暂不迁移；后续以新的行动和伤害上下文重新接入。

## 验证

```text
npm run check:rules
npm run build
```

`scripts/v2-check.mjs` 覆盖房间图、尺寸、锁门机关、隐藏门、翻牌、进门冻结、到达格、八码寻路和敌人回合。

## 第二阶段：伤害、敌人与竖屏界面

- 伤害结算已从 `GameRun` 拆到 `rules/modifiers.js`：基础攻击、临时 buff、剩 1 耐久的减半、属性克制、圣遗物与未来地形修正共用同一条管线。
- 现阶段属性为劈砍、穿刺和钝击，对应血肉、甲壳和灵体；克制为 ×1.6，受制为 ×0.65。界面不会显示自动算分，只记录最终伤害与克制提示。
- 圣遗物拥有独立收藏和最多 5 个激活栏，以及候选生成、伤害修正和事件钩子接口。当前接入三件用于验证高伤害构筑的圣遗物；房间中如何出现圣遗物和完整三选一交互留待内容阶段确定。
- 第一批敌人改为数据定义与行为分派：血肉近战、甲壳重甲和灵体远程都使用 `stationary` 行为，后续追击、伏击、召唤等只需增加行为定义。
- HUD 仅适配竖屏手机。页面固定在 `100dvh` 内，不使用可滚动状态栏、操作区、背包或日志；棋盘自动占据其余空间。背包规格明确为 4 行×6 列。
- 新增 `npm run lint`。ESLint 只检查 V2 源码和 V2 规则测试，明确排除 `src/legacy`。
