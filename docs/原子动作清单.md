# 原子动作清单

本文记录当前代码中已经拆出的原子动作，以及它们如何组合成游戏功能。目标是让翻牌、伤害、状态、装备和遗物效果都能通过稳定的小动作组合，而不是在每个遗物中增加一套新的流程分支。

相关实现主要位于：

- [`src/game/state.js`](../src/game/state.js)：游戏状态、动作组合和结算入口。
- [`src/game/rules/resolution.js`](../src/game/rules/resolution.js)：结算队列与阶段顺序。
- [`src/game/rules/status.js`](../src/game/rules/status.js)：可叠加、独立计时的状态。
- [`src/game/rules/combat.js`](../src/game/rules/combat.js)：纯伤害和攻击计算。
- [`src/game/model/backpack.js`](../src/game/model/backpack.js)：行囊占位与旋转。
- [`src/game/model/loadout.js`](../src/game/model/loadout.js)：双手装备栏。

## 一、什么算原子动作

原子动作只负责一个明确的状态变化，或者一次没有副作用的计算。它不应该偷偷推进回合、扣理智、触发反击或发放奖励。

组合功能则负责安排多个原子动作的顺序，并通过 `cause`、`source`、`channel` 等上下文说明来源。这样同一个动作可以被普通操作、陷阱、圣遗物和主动技能复用。

当前约定：

1. 成本显式传入，例如翻牌的理智消耗由 `_revealCard(..., { sanCost })` 决定。
2. 伤害来源显式传入，例如 `source: 'retaliation'`、`source: 'trap:explosion'`。
3. 会触发其他能力的伤害和绕过触发的直接伤害分开实现。
4. 复杂流程使用 `EffectQueue` 的阶段结算，能力获得顺序由同一优先级的 `sourceOrder` 保持。

## 二、当前原子动作清单

### 1. 牌面与可见性

| 原子动作 | 当前接口 | 只负责什么 | 明确不负责什么 |
| --- | --- | --- | --- |
| 翻开牌面 | `flipCard(card, { cause })` | 将牌标记为已翻开，并发送翻牌动画事件 | 不扣理智、不解析牌、不触发怪物攻击 |
| 查询可翻牌 | `flippableCards(range)` | 返回当前回合按翻牌距离可以翻开的全部隐藏牌 | 不翻牌、不扣理智、不推进回合 |
| 扣除理智 | `spendSanity(amount, { source })` | 从当前理智中扣除实际可扣除值 | 不翻牌、不造成伤害、不推进回合 |
| 查看邻牌 | `peekRandomNeighbor(card)` | 随机选择一张相邻未翻开的牌并标记 `peeked` | 不翻开牌、不扣理智 |
| 牌状态增删 | `addCardStatus`、`removeCardStatus`、`hasCardStatus` | 给单张牌增加、移除、查询状态 | 不自动处理牌的其他效果 |

flipCard 和 spendSanity 是本轮重点拆开的两个动作。它们可以单独使用，因此战吼可以翻牌但不扣理智，声响陷阱可以翻牌并按自己的规则扣理智。

陷阱在 _resolveFlip 中先发送 trap:before-trigger 结算事件，再标记为已触发并执行爆炸/声响效果。拆弹专家通过这个拦截点取消陷阱，翻牌入口本身不需要知道具体遗物。

### 1.1 棋盘实体与移动

场上的怪物、召唤物和普通牌都继续使用同一个 `board` 数组；阵营和
`entityKind` 只是牌对象上的参与规则字段，不另建一套棋子实体。

| 原子动作 | 当前接口 | 只负责什么 |
| --- | --- | --- |
| 查询格子 | `getBoardCardAt(c, r)`、`isCellOccupied(c, r)` | 按坐标查询未消耗牌和占位状态 |
| 查找空格 | `findEmptyBoardCell(options)` | 按当前楼层棋盘边界找一个空格 |
| 移动牌 | `moveCard(card, c, r, options)` | 移动到目标格，按策略拒绝或交换碰撞 |
| 交换位置 | `swapCardPositions(a, b, options)` | 交换两张牌的坐标，可选择翻开被撞牌 |
| 推动 | `pushCard(card, options)` | 选择八方向并调用 `moveCard` 推动一格 |
| 随机换位 | `randomSwapCard(card)` | 将牌与随机棋盘格交换，不自动翻牌 |
| 生成牌 | `spawnCard(raw, options)` | 在空格创建牌并发送 `card:spawned` |
| 召唤史莱姆 | `spawnSlime()` | 用通用生成动作创建友方召唤物；无空格时失败 |
| 转换牌 | `transformIntoSlime(card)` | 保留坐标和 uid，把死亡敌人转换为友方史莱姆 |
| 消灭牌 | `destroyCard(card)` | 将召唤物设为死亡并发送 `card:destroyed` |
| 友方目标选择 | `selectCombatTarget(attacker)` | 按距离和 uid 选择敌人当前应优先攻击的友方召唤物 |

### 2. 玩家资源

| 原子动作 | 当前接口 | 说明 |
| --- | --- | --- |
| 增加护甲 | `addArmor(amount)` | 增加护甲，不超过逻辑上的非负范围 |
| 恢复理智 | `gainSanity(amount, context)` | 恢复实际可恢复的理智，不超过最大值 |
| 治疗 | `healPlayer(amount, context)` | 按最大生命值上限恢复生命，并发送 `player:healed` 结算事件 |
| 扣理智 | `spendSanity(amount, context)` | 扣除实际存在的理智；当前不把“获得理智”与之混在一起 |
| 玩家受伤 | `receiveDamage(amount, context)` | 计算受伤修正、执行 `damage:before`、处理护甲吸收和生命损失，并发送 `damage:received` |

这些动作虽然会发送结算事件，但每次只处理一种资源变化，因此仍作为基础结算动作使用。护甲吸收发生在 `receiveDamage` 内部，护甲不会被单独写进每个攻击流程。

### 3. 怪物伤害与纯计算

| 原子动作 | 当前接口 | 说明 |
| --- | --- | --- |
| 造成可触发伤害 | `dealMonsterDamage(card, amount, context)` | 应用出伤害修正，扣除怪物生命，并发送 `damage:dealt` |
| 造成召唤物伤害 | `dealCardDamage(card, amount, context)` | 对棋盘上的友方/中立怪物牌造成独立通道伤害，不套用玩家攻击修正 |
| 造成直接伤害 | `dealDirectMonsterDamage(card, amount)` | 直接扣除怪物生命，绕过修正、连锁触发和击杀奖励；用于反伤等隔离效果 |
| 转为金币并击杀 | `convertMonsterToGold(card, options)` | 将当前生命转为金币并进入普通 _onMonsterKilled 流程 |
| 范围伤害组合 | `dealAreaMonsterDamage(center, amount, options)` | 找到范围内已翻开的存活怪物并逐个调用 `dealMonsterDamage`；死亡检查由调用者负责 |
| 随机溅射组合 | `resolveRandomAttackSplash(center, amount, options)` | 优先伤害距离范围内随机敌人；无敌人时选择范围内隐藏牌翻开 |
| 范围翻牌组合 | `revealCardsInRadius(center, options)` | 找到范围内隐藏牌并逐个调用 `_revealCard`；理智费用和本回合不攻击集合由调用者指定 |
| 随机翻牌组合 | `revealRandomCard(options)` | 从未翻开牌中随机选择一张并调用 `_revealCard` |
| 计算攻击伤害 | `computeAttackDamage(weapon, card, buff, context)` | 计算一次武器攻击的最终数值，不直接改状态 |
| 计算通用修正 | `computeDamage`、`modifyByRelics` | 计算倍率、加成、耐久影响等，不直接改状态 |
| 消耗武器耐久 | `consumeWeaponDurability(weapon, options)` | 单独结算耐久/维护效果并触发损坏事件；可传 `consume: false` |
| 处理武器损坏 | `resolveWeaponBroken(weapon, reason)` | 统一发送武器损坏事件并交给后续能力处理 |
| 怪物反击 | `resolveMonsterRetaliation(card, weapons, options)` | 单独执行背袭/放逐检查、反击伤害和荆棘消耗 |

`dealMonsterDamage` 不自动调用击杀奖励。伤害之后是否死亡、是否发放金币、是否触发掉落，由外层流程在死亡阶段显式处理；这样 DOT、溅射和连锁伤害也能复用同一规则。

### 4. 状态与计时

`StatusStore` 提供以下基础动作：

- `add(status)`：增加状态，支持 `independent`、`replace`、`refresh`、`max` 等叠加规则。
- `remove(uid)`：移除一个具体状态实例。
- `has(id)`、`get(id)`、`all()`、`totalAmount(id)`：查询状态。
- `tick()`：让独立状态各自减少一回合，并移除到期实例。
- `serialize()`：导出状态；读档时由 `GameState` 重建 `StatusStore`。

因此“攻击造成流血”“翻牌后的背刺”“放逐一回合”“五回合后诅咒爆发”都可以先添加状态，再由统一的回合状态阶段处理，而不是各自维护一套计时器。

### 4.1 怪物技能

怪物技能由 `src/data/monster-skills.js` 定义，`MonsterSkillEngine` 只按触发时机收集数据效果，不按怪物 id 写战斗分支。

| 原子动作 | 当前接口 | 说明 |
| --- | --- | --- |
| 查询技能 | `monsterSkills.skillsFor(card)` | 根据牌面上的技能 id 获取技能定义 |
| 触发单牌技能 | `monsterSkills.trigger(card, trigger, context)` | 将技能效果送入 `EffectQueue`，按技能冷却执行 |
| 触发全场技能 | `monsterSkills.triggerBoard(trigger, context)` | 对已翻开的存活敌人逐个触发指定时机 |
| 技能冷却 | `monsterSkills.tickCooldowns()` | 每回合开始统一减少所有怪物技能冷却 |
| 怪物技能攻击 | `monsterSkillAttack(card, options)` | 复用怪物攻击力、护甲、生命和理智结算 |
| 随机邻格移动 | `moveMonsterToRandomNeighbor(card, options)` | 只移动到空的相邻格，不覆盖其他牌 |
| 怪物状态减伤 | `dealMonsterDamage` 内的 `damageReduction` | 由状态数据提供减伤，不在技能流程中写死 |

当前触发点包括：`reveal`、`turn:start`、`attack:after`、`damaged`。翻出即攻击的怪物仍加入本回合免攻击集合，避免被普通怪物攻击流程重复攻击。

### 5. 行囊和装备容器

这些是模型层的容器原子动作，不自动消耗回合：

- 行囊：`BackpackGrid.add`、`removeAt`、`removeByUid`、`move`、`rotate`、`canPlace`、`firstFit`。
- 装备栏：`WeaponLoadout.equip`、`removeAt`、`removeByUid`、`findByUid`、`canEquip`。
- 状态层包装：`addToHand`、`removeHandAt`、`removeHandByUid`、`moveBackpack`、`rotateBackpack`、`discardBrokenWeapon`。

行囊的坐标只描述占位和旋转，不参与物品之间的联动。以后如果出现“放在行囊中才生效”的物品，应通过 `card:picked`、`item:stored` 等事件或标签组合，不应把特殊规则写进网格碰撞算法。

## 三、游戏功能如何由原子动作组合

### 1. 普通翻牌

```text
flip(uid)
  → 检查阶段、距离和当前状态
  → _tickTurn(card)
  → _revealCard(card)
      → flipCard(card)
      → spendSanity(怪物费用或传入费用)
      → _resolveFlip(card)
      → card:revealed 事件
  → 检查玩家死亡
  → _monsterAttackAll(本次翻出的怪物除外)
  → 再次检查死亡并保存状态
```

`_revealCard` 是“翻牌组合动作”，不是原子动作。它把 `flipCard`、理智消耗和牌面解析按固定顺序串起来。

### 2. 战吼：翻开本层所有敌人

```text
revealAllMonsters({ sanCost: 0 })
  → 对每个隐藏怪物执行 _revealCard
      → flipCard
      → 不扣理智
      → 解析怪物牌
      → card:revealed
```

战吼不调用普通 `flip`，因此不额外推进回合，也不调用本次行动后的全场反击。每只新翻出的怪物仍记录为本回合不攻击，下一次行动再按普通怪物规则处理。

### 3. 声响陷阱

```text
翻开陷阱
  → _revealCard(陷阱本身，不消耗怪物理智)
  → 找到范围内的隐藏怪物
  → 对每个目标执行 _revealCard({ sanCost: 1 })
  → 记录 noAttackUids
  → 陷阱变为空牌位
```

声响陷阱复用翻牌组合，但可以传入自己的理智费用；它不翻开范围内的其他牌。

### 4. 爆炸陷阱

```text
翻开陷阱
  → _revealCard
  → receiveDamage(2, { source: 'trap:explosion' })
  → 对范围内已翻开的怪物逐个 dealMonsterDamage
  → 对死亡怪物执行死亡结算和掉落
  → 陷阱变为空牌位
```

爆炸伤害使用普通可触发伤害，因此可以触发伤害相关能力；未翻开的怪物不在目标集合中。

### 5. 一次攻击

```text
attack(uid)
  → 检查目标是否可攻击、是否被放逐
  → _tickTurn(card)：开始一个玩家回合，推进回合计数并结算回合开始效果
  → 为每把手中武器计算 computeAttackDamage
  → dealMonsterDamage（攻击伤害）
  → 扣除耐久并执行 resolveWeaponBroken
  → RETALIATION 阶段：目标 receiveDamage
  → SECONDARY 阶段：处理吸血、燃烧、减速、溅射或连锁等后续效果
  → DEATH 阶段：_onMonsterKilled
  → AFTER_ACTION 阶段：消耗 buff、施加放逐等
  → TURN_END 阶段：除目标外的其他存活敌人各执行一次 _monsterAttackAll
  → 检查玩家死亡并结束本回合
```

双持仍然是一次 `attack` 行动，只是同一行动内有两次 `strike`。放逐在反击之后的 `AFTER_ACTION` 阶段生效，因此不会让施加放逐的这次攻击免疫反击；背刺则在反击阶段被消耗。

攻击动作由三个可复用部分组合：

```
攻击伤害（每把武器一次）
  → resolveMonsterRetaliation
  → consumeWeaponDurability

普通攻击 = 上述三步 + 1 次回合推进
连斩后续攻击 = 攻击伤害 + resolveMonsterRetaliation（consumeWeaponDurability: false）
```

`_monsterAttackAll` 是一个独立的敌人威胁原子动作。普通攻击在 `TURN_END` 调用它并传入目标 uid 作为排除项；攻击过程中由溅射、战吼或其他效果新翻出的敌人 uid 会进入本次行动的 `noAttackUids` 集合；连斩后续攻击不调用它，因此一次攻击行动无论双持还是连斩，都不会让同一只非目标敌人在一个回合内重复攻击。若某个敌人在威胁阶段开始前已经死亡或被移除，它不会获得排队中的攻击机会；玩家生命归零后，威胁阶段立即停止。

连斩回响只在当前目标被击杀后继续，从当前目标位置按上、右、下、左、上右、下右、下左、上左寻找下一个敌人；后续目标未被击杀或没有相邻敌人时停止。

本批新增的几个攻击组合：

- 流血：攻击的 `SECONDARY` 阶段调用 `addCardStatus`，每次施加都用 `replace` 刷新 5 回合；回合状态阶段调用 `dealMonsterDamage` 造成 2 点 DOT。
- 迅捷换手：切换装备后发送 `weapon:switched`，用 `weapon:switchCostTurn` 将行动成本改为 0，并在下一次 `attack:damage` 使用一次性 ×2 修正。
- 破损溅射：耐久结算完成后，在 `SECONDARY` 阶段调用 `dealAreaMonsterDamage`；范围伤害独立检查死亡和奖励。

### 6. DOT、诅咒和击杀奖励

```text
回合状态阶段
  → StatusStore.tick / 到期检查
  → dealMonsterDamage（流血、燃烧、诅咒）
  → 检查 monsterHp <= 0
  → _onMonsterKilled
      → 金币、钥匙、物品掉落
      → 吸血或理智恢复等击杀后效果
```

DOT 可以触发击杀奖励，因为它使用 `dealMonsterDamage` 并在伤害后明确进入死亡结算。反伤使用 `dealDirectMonsterDamage`，按规则不继续触发其他伤害效果。

死亡爆裂组合为：

```text
monster:killed
  → revealCardsInRadius（免费调用 _revealCard，翻开周围隐藏牌）
  → dealAreaMonsterDamage（对周围已翻开的敌人造成 2 点伤害）
  → 对被范围伤害杀死的敌人再次执行 _onMonsterKilled
```

武器轮换组合为：

```text
turn:start
  → 每 3 回合调用 spawnRandomWeapon
  → BackpackGrid.add / firstFit
  → weapon:spawned
```

如果行囊放不下，生成动作返回 `null`，不会强行破坏已有占位。

### 棋盘移动、召唤和阵营承伤

推动组合为：

```text
攻击伤害与死亡检查
  → pushCard(目标敌人, 随机八方向)
      → 目标格为空：直接移动
      → 目标格有牌：swapCardPositions
          → 需要时 flipCard / _revealCard 被撞牌
```

召唤组合为：

```text
turn:start（第 10、20……回合）
  → findEmptyBoardCell
  → spawnCard(史莱姆, { faction: 'ally', entityKind: 'summon' })
  → card:spawned
```

敌人攻击组合为：

```text
_monsterAttackAll（一个回合内每个敌人最多一次）
  → selectCombatTarget(攻击者)
  → 有友方召唤物：dealCardDamage → destroyCard（死亡时）
  → 没有友方召唤物：receiveDamage → spendSanity(1)
```

因此史莱姆占据一个棋盘格并会吸引敌人攻击；没有空格时召唤不会覆盖其他牌。死亡转换只替换牌的定义、阵营和生命，不改变坐标，也不产生第二个实体。

不消耗回合的整理背包、拾取战利品、使用药水/buff、丢弃和装备栏选择等操作不会调用 `_tickTurn` 或 `_monsterAttackAll`。消耗回合的操作必须按“回合开始 → 玩家动作 → 敌人威胁 → 死亡检查”的顺序组合。

等待一回合组合为：

```text
waitTurn()
  → 检查当前是否处于 explore 阶段
  → _tickTurn（回合开始、冷却、持续状态和周期效果）
  → _monsterAttackAll（所有已翻开存活敌人各攻击一次）
  → 检查玩家死亡并保存状态
```

等待不会清除待使用 buff、移动牌面或改变行囊；理智耗尽时交由 `_madnessAct` 遵守失控规则。

主动技能组合为：

```text
短按技能按钮
  → castActiveSkill
  → 检查当前技能独立冷却
  → _tickTurn（技能声明 consumesTurn 时）
  → RelicEngine.invokeActiveSkill
  → active-skill EffectQueue
  → 写入该技能冷却（当前默认 10 回合）
  → _monsterAttackAll（可用 noAttackUids 排除本次新翻出的敌人）

长按技能按钮
  → 打开技能图标选择列表（不耗回合）
  → 点击图标
      → selectActiveSkill(skillId)
      → 选中的技能不同于当前技能时 _tickTurn
      → _monsterAttackAll
  → 长按图标
      → 打开该技能说明和冷却面板（不选择、不耗回合）
```

长按由 `src/ui/long-press.js` 统一处理，基于 Pointer Events，触摸、鼠标和手写笔共用同一套按下/移动取消/抬起判定；移动超过容差、系统取消或右键菜单都会取消长按，不会误触发技能。

技能提供者不只限于圣遗物。`GameState.activeSkillEntries()` 按稳定顺序合并激活圣遗物、装备栏武器和行囊物品上的 `activeSkill` 定义；每个提供者通过自己的运行时字段保存冷却，因此后续添加武器技能或物品技能时无需增加新的按钮或输入分支。

### 7. 反伤

```text
receiveDamage(玩家受到的伤害)
  → damage:before（可消耗理智等资源并减少本次伤害）
  → 护甲吸收
  → damage:received 事件
  → 反伤能力读取事件上下文
  → dealDirectMonsterDamage(攻击者, 反伤数值)
```

反伤不再重新进入普通攻击链，不触发新的反伤、溅射、连锁或击杀奖励，避免无限递归。

### 8. 吸血和治疗相关效果

```text
dealMonsterDamage
  → damage:dealt
  → 吸血能力计算恢复量
  → healPlayer
  → player:healed
```

由于治疗也有独立事件，“捡起物品回血”“攻击吸血”“每隔若干回合回血”可以复用同一个治疗动作。未来若出现“治疗时获得护甲”，只需订阅 `player:healed`，不需要修改每个治疗来源。

理智护盾组合为：

```text
receiveDamage
  → damage:before
  → spendSanity（最多抵挡本次伤害的一半）
  → 剩余伤害进入护甲和生命结算
```

理智护盾不修改普通伤害修正通道，因此不会把“消耗理智”伪装成倍率变化；每次实际消耗量会记录在 `sanityAbsorbed` 中。

### 9. 预览邻牌

```text
card:revealed
  → peekRandomNeighbor(card)
  → 目标牌设置 peeked = true
  → 渲染层显示半透明牌背
```

预览不会调用 `flipCard`，因此不会触发牌面效果，也不会扣理智。

### 10. 行囊和装备操作

```text
拾取物品
  → BackpackGrid.canFit / firstFit
  → BackpackGrid.add
  → card:picked（未来可补充 item:stored）

装备武器
  → WeaponLoadout.canEquip
  → WeaponLoadout.equip
  → 必要时移出冲突装备

使用磨刀石或维护油
  → 选择目标武器
  → 修改武器实例属性
  → 移除道具
  → 如需消耗回合，再调用 _tickTurn 和 _monsterAttackAll
```

容器动作和行动消耗分离，因此“翻牌后自动拿起武器”“不消耗回合的拾取”“消耗回合的道具使用”可以分别组合。

## 四、以后新增机制时的组合规则

新增圣遗物、怪物技能或事件时，优先按以下顺序实现：

1. 先确认它改变的是哪一个原子动作或结算事件。
2. 尽量增加一个数据化的修正通道，例如 `damage:incoming`、`attack:damage`、`weapon:durabilityCost`。
3. 如果只是顺序不同，使用 `EffectQueue` 阶段和 `sourceOrder`，不要复制整段攻击流程。
4. 如果效果需要特殊隔离，使用明确的动作变体，例如 `dealDirectMonsterDamage`，不要在普通伤害函数里堆叠遗物编号判断。
5. 每个新原子动作至少补充“单独调用”的测试；每个新机制再补充一次完整组合流程测试。

## 五、仍需继续原子化的候选动作

以下能力已经能通过现有流程实现，但还没有独立成稳定接口，后续建议逐步补齐：

- `moveCard`、`swapCardPositions`、`findEmptyBoardCell`、`pushCard`、`randomSwapCard`：已实现，供推动、交换、传送和召唤复用。
- `spawnCard` / `removeCard` / `transformIntoSlime`：已实现，统一史莱姆和其他棋盘牌的生命周期。
- `selectCombatTarget` / `dealCardDamage` / `destroyCard`：已实现，统一召唤物的阵营目标选择和承伤。
- `applyStatus`、`expireStatus`：让怪物技能和圣遗物不需要直接操作 `StatusStore` 细节。
- `selectTargets`：统一范围、阵营、已翻开/未翻开和随机目标筛选。
- `invokeActiveSkill`：已实现主动技能的提供者选择、费用/行动消耗、独立冷却和结算入口。
- `createDrop` / `grantReward`：将怪物掉落、奖励、商店和事件中的物品发放统一起来。

这些接口不是为了增加抽象层数量，而是为了让未来的一百多个圣遗物继续由“动作 + 条件 + 结算阶段”组成，避免出现按圣遗物编号不断扩大的分支结构。
