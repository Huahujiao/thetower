# 圣遗物系统（第五阶段）

## 1. 运行时边界

圣遗物只属于当前这一局。新开一局时，收藏、激活栏和圣遗物运行时状态全部清空；当前版本没有局外图鉴或永久成长系统。

圣遗物分成两个层级：

- **本局图鉴**：`relicCollection`，按获得顺序记录已获得的圣遗物，不重复、不出售。
- **激活栏**：`activeRelics`，最多 5 个，只有激活的圣遗物参与规则结算。

圣遗物一旦获得，就从本局所有后续生成池中移除。没有选择、没有购买、没有翻出，或离开楼层时尚未获得的圣遗物，都不会消耗，之后仍可再次出现。

开局三选一是唯一的立即激活例外：所选圣遗物加入图鉴并立即激活。之后通过奖励、商店、事件、掉落或翻牌获得的圣遗物，先进入图鉴，只有在商店中才能激活或停用。

## 2. 数据驱动接口

具体圣遗物定义放在 `src/data/relics.js`，运行时不根据圣遗物 ID 写分支。当前实际实现 46 个；“可双持双手武器”暂不纳入图鉴，因为双持单手已经提供双击和多词条收益，双手武器自身也有更高基础攻击与稀有词条，继续增加双持双手会主要扩大数值而不是增加新的决策维度：远视之眼、开路先机、双刃契约、守望之眼、血之记忆、破刃余烬、钥匙共鸣、猎杀印记、血债铸币、丰饶刻印、循环壁垒、以逸待劳、重击誓约、荆棘回响、鲜血回响、潮汐刻度、胜利在望、狂战之心、拾荒者之心、清明之眼、逆理之心、滋养之刃、拆弹专家、绝不手软、铁壁刻印、黄金锋芒、背袭之影、窥见薄纱、战吼、回响溅射、耐久欺诈、诅咒烙印、虚空放逐、流血印记、迅捷换手、破损溅射、武器轮换、死亡爆裂、理智护盾、冲撞余势、黏液召唤、死者新生、混沌换位、连斩回响、号令之声、藏匿之影。

基础批次效果的数值解释为：翻牌距离 +1；主动攻击及其反击伤害 ×2，敌人主动攻击不翻倍；每个已翻开存活敌人使受到的攻击伤害 -1，但每个伤害包至少 1 点；同一目标后续攻击 +1；耐久度为 0 的武器自动丢弃，并随机使另一把可用武器攻击力 +3（优先手中的武器）；每层每个钥匙碎片使伤害倍率 +0.3，进入下一层清零；击杀 +1 金币；奖励数量 +1；以逸待劳满血伤害倍率 1.5，每损失完整 10% 生命倍率 -0.1；攻击伤害 ×2 但下一回合不可攻击。

低风险扩展批次效果的暂定数值为：受到敌人攻击反伤 30%；主动攻击回血造成伤害的 30%；每 2 回合回复 2 生命；出口距离 1~5 格额外伤害 5~1；生命损失比例转化为最多 50% 增伤；拾取物品回复 1 理智；满理智或 0 理智时分别最多获得 30% 增伤；每次回血使一把手中武器攻击力 +1；敌人低血量时最多获得 50% 增伤；每回合获得 3 护甲；每 10 金币使武器攻击力 +1。以上数值属于首轮测试值，后续可以独立调整。

第二批中等改动暂定为：背袭标记在第一次攻击的反击阶段消耗；窥见薄纱在翻牌时标记一张相邻未翻开的牌并以半透明信息显示；战吼击杀计数跨层累计，第 10 次击杀只翻牌、不消耗理智；耐久欺诈将攻击时耐久倍率固定为 1，但每次实际消耗 +1；诅咒持续 5 回合后造成 20 点持续伤害且不可重复施加；放逐在本次反击完成后生效，持续 1 回合。
第三批结算扩展暂定为：流血状态使用独立计时并刷新不叠加；迅捷换手通过 `weapon:switched` 和 `weapon:switchCostTurn` 实现；破损溅射和死亡爆裂复用范围伤害/范围翻牌组合动作；武器轮换通过统一的随机武器生成接口入包；理智护盾在 `damage:before` 阶段扣理智并限制每次最多抵挡一半伤害。
棋盘实体扩展暂定为：冲撞余势调用八方向 `pushCard`，撞到隐藏牌时翻开并交换坐标；黏液召唤每 10 回合调用 `spawnSlime`，无空格则失败；死者新生在 `monster:killed` 后调用 `transformIntoSlime`；混沌换位在攻击后调用 `randomSwapCard`，交换时不自动翻牌。主动技能扩展暂定为：号令之声使用 `pullMonstersNearEntry`；藏匿之影使用 3 回合藏匿状态和 `revealRandomCard`。
本批新增效果：开路先机统计当前回合可翻开的未翻牌并转为攻击固定加成；回响溅射优先对距离 2 内随机已翻开敌人造成一次伤害，否则免费选择范围内一张牌翻开（若为敌人按普通翻牌扣理智）；血债铸币第 10 次攻击把仍存活的目标按当前生命转为金币并进入正常击杀流程；循环壁垒每 5 回合获得 5 点护甲；拆弹专家在 `trap:before-trigger` 拦截陷阱并恢复理智与生命；连斩回响在击杀后按固定八方向继续执行不消耗耐久的攻击，直到目标未被击杀或没有相邻敌人。

### 原子动作层

规则代码将“动作本身”和附带成本/后续效果拆开。当前已提供：

- `flipCard(card)`：只把牌翻到正面并发出翻牌动画，不扣理智、不执行牌面效果；
- `spendSanity(amount)`：只扣除理智并返回实际扣除值；
- `gainSanity(amount)`：只恢复理智并返回实际恢复值；
- `_revealCard(card, options)`：组合 `flipCard`、`spendSanity`、牌面效果和 `card:revealed` 事件，供普通翻牌使用；
- `dealMonsterDamage`、`dealDirectMonsterDamage`、`receiveDamage`、`healPlayer`、`addArmor`：分别处理可触发效果的伤害、原子伤害、玩家受伤、回血和护甲。
- `dealCardDamage`、`destroyCard`、`selectCombatTarget`：处理召唤物承伤、消灭和敌人优先目标选择。
- `dealAreaMonsterDamage`、`revealCardsInRadius`：将范围伤害和范围翻牌作为可复用的组合动作；范围动作仍由调用者决定是否检查死亡、奖励和后续触发。
- `getBoardCardAt`、`findEmptyBoardCell`、`moveCard`、`swapCardPositions`、`pushCard`、`randomSwapCard`、`spawnCard`、`transformIntoSlime`：处理棋盘占位、移动、碰撞和召唤，不引入独立实体模型。
- `damage:before`：伤害落地前的可变结算上下文；理智护盾等效果可以在这里消耗资源并减少本次伤害。
- `weapon:switched`、`weapon:spawned`：装备切换和生成武器的通用事件；`weapon:switchCostTurn` 是切换是否消耗回合的修正通道。
- `activeSkill` + `actions['active-skill']`：主动技能元数据和数据驱动效果；`castActiveSkill` 短按施放，长按按钮打开图标列表，`selectActiveSkill(skillId)` 按选择切换并消耗回合，长按图标打开说明。每个技能的 `cooldown` 独立计时，未声明时默认 10 回合。
- 技能提供者不限定为圣遗物：`GameState.activeSkillEntries()` 还会扫描装备栏和行囊物品上的 `activeSkill` + `actions['active-skill']`，后续武器/物品可以直接复用同一按钮和结算入口。

因此战吼可以复用翻牌流程但传入 `sanCost: 0`，声响陷阱则传入自己的理智成本；后续事件、技能和遗物不需要复制整段翻牌逻辑。

定义可以声明三类能力：

```js
{
  id: 'relic_id',
  name: '名称',
  desc: '描述',
  hooks: {
    'turn:start': ({ state, relic }) => effects,
    'card:revealed': ({ state, relic }) => effects,
    'monster:killed': ({ state, relic }) => effects,
  },
  modifiers: {
    'damage:outgoing': ({ state, relic }) => [
      { operation: 'percentAdd', phase: 'damage', value: 0.05 },
    ],
    'weapon:power': ({ state, relic, weapon }) => [
      { operation: 'add', value: 3 },
    ],
  },
  actions: {
    'relic:active-skill': ({ state, relic }) => effects,
  },
}
```

- `hooks` 接入现有 `TriggerRegistry` 和 `EffectQueue`，由阶段、优先级和获得顺序统一排序。
- `modifiers` 接入数值修正器，同一阶段的百分比加成按加法合并。
- `actions` 为后续主动技能预留统一入口。
- `relic.runtime` 保存该圣遗物独立的计数器、持续回合和其他运行时数据。

当前批次的获得入口已经接入开局三选一、层间奖励和商店货架；事件、怪物掉落和直接翻牌可以直接调用 `GameState.acquireRelic(id, { source })`，后续再接入具体内容。

圣遗物按照获得顺序执行，而不是按照当前激活栏的排列顺序执行。更换激活栏只改变“是否生效”，不会改变获取顺序。

## 3. 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/data/relics.js` | 圣遗物定义、候选生成、显示文本 |
| `src/game/model/relics.js` | 本局收藏、激活栏、唯一获取、运行时状态、序列化 |
| `src/game/rules/relics.js` | 将定义接入触发器、修正器和主动效果 |
| `src/game/state.js` | 商店激活边界、存档、公共 API |
| `src/game/rules/resolution.js` | 统一效果队列与结算顺序 |

新增圣遗物时原则上只需要增加数据定义和必要的通用事件/修正通道，不应在攻击、翻牌、怪物死亡等流程中加入针对具体 ID 的判断。

## 4. 后续扩展

当前已预留以下通道：

- `turn:start`、`card:revealed`、`monster:killed`、`key:collected`、`floor:start`、`weapon:broken`、`weapon:discarded` 等事件触发；
- `weapon:power`、`damage:outgoing`、`damage:incoming`、`damage:retaliation`、`attack:damage` 等数值修正；
- `damage:before`、`damage:received`、`damage:dealt`、`player:healed`、`card:picked`、`card:spawned`、`card:removed`、`card:transformed`、`card:destroyed`、`weapon:switched`、`weapon:spawned` 等低风险内容事件；
- 牌面 `StatusStore`，支持持续回合、独立/替换叠加规则和存档；
- 棋盘牌的 `faction`、`entityKind`、`summoned` 字段，以及通用的移动/召唤/转换动作；
- `weapon:durabilityFactor`、`weapon:durabilityCost`、`weapon:switchCostTurn` 武器耐久与切换结算通道；
- 独立运行时状态与存档；
- 主动技能 `actions`；
- 主动技能槽、短按施放/长按打开图标列表、图标点击选择/长按说明，以及切换后的回合消耗、独立冷却和敌人反击；
- 商店专属的激活/停用命令；
- 未来可增加事件、移动、召唤、状态、奖励和资源等通道。

如果未来加入局外成长，应另建 `playerProfile.metaProgress`，不能写入当前的 `runState.relics`。
