# 《黑塔》代码实现说明

> 技术选型、代码结构、关键机制实现思路。阅读代码前先看本文。
> 机制设计见 [核心机制.md](核心机制.md)；数值来源见各系统文档。

## 1. 技术选型

| 项 | 选择 | 说明 |
|----|------|------|
| 构建 | **Vite** | 开发服务器（`npm run dev`，端口 3000）+ 打包；无框架，纯 ES Module |
| 3D 渲染 | **Three.js** | 牌堆网格、翻牌动画、环境灯光、牌面 Canvas 纹理 |
| UI | **原生 DOM + CSS** | HUD（状态栏/行囊/装备栏/层间面板/浮层按钮）手写 |
| 语言 | 原生 JavaScript（ESM） | 无 TypeScript，无组件框架 |
| 数据 | 静态 JS 模块 | 卡牌数据集中在 `src/data/cards.js`，与文档对应 |
| 存储 | localStorage | 自动存档（`heita_save_v1`），带版本号 |
| 平台 | 手机竖屏优先 | 仅竖屏设计，无横屏分支；触摸优先 |

开发环境注意：npm 使用淘宝镜像（`registry.npmmirror.com`，官方源国内慢）；开发服务器**由用户手动启动**，Agent 不自动拉起。

## 2. 项目结构

```
three-vite-demo/
├─ index.html               # 页面骨架（禁缩放/选中/橡皮筋，#app 由 HUD 生成）

├─ docs/                    # 设计文档（核心机制.md 为总览）
└─ src/
   ├─ main.js               # 入口：组装 state/HUD/Scene，监听重建
   ├─ styles.css            # 全局样式（HUD 在 ui/hud.css）
   ├─ data/cards.js         # ★ 全部卡牌数值 + 牌堆/商店/奖励生成器
   ├─ data/relics.js        # 圣遗物定义与候选生成器
   ├─ game/
   │  ├─ state.js           # ★ 状态机与现有行动 API
   │  ├─ core/              # 事件、命令、随机数入口
   │  ├─ model/             # 行囊网格、线性容器与双手装备模型
   │  └─ rules/             # 战斗、修正器、效果队列、查询、状态、触发器、怪物技能

```

## 3. 模块职责

### 3.1 `src/data/cards.js` — 数据与生成器（纯函数，无副作用）

- **卡牌常量**：`MONSTERS / WEAPONS / POTIONS / ITEMS / BUFFS / GOLD_CARDS / KEY_CARD / EXIT_CARDS / ENTRY_CARD`，全部带 `id`；`T` 枚举牌型；`DEFS_BY_ID` 全量查表（存读档用）。
- **价格表**：`POTION_PRICE / ITEM_PRICE / BUFF_PRICE`、`weaponPrice`（攻×2 + 稀有度加价）、`priceOf`（任意 def → 买入价）；出售价 = 买入价 5 折（`state.sellPrice`）。
- **楼层配置**：`FLOORS[7]`（网格、各牌型数量、精英/Boss 标记）。
- **牌堆生成** `buildFloorDeck(floor, mod)`：固定牌（入口/钥匙/出口）→ 按配比填充 → 4% 概率替换普通牌为陷阱 → 污染标记。修饰参数来自环境/路线（`ENVIRONMENTS` / `ROUTES`）。
- **生成器**：`buildShopStock`（8 格商店，包含 1 个未获得圣遗物机会）、`buildRewardChoices`（奖励选项，包含 1 个未获得圣遗物机会）、`rewardText / buffText / itemText`（展示文案）。
- 武器稀有度权重 `W_TIERS`（A/B/C/Z 按层区间）、怪物分层池、buff 层池 `buffPoolForFloor`。

### 3.2 `src/game/state.js` — 状态机与现有行动 API

- **`GameState` 类**：持有 `player / hand / equip / board / log / rest` 等全部运行时状态；`hand` 是 `BackpackGrid` 的物品数组视图，真实状态保存每件物品的坐标与旋转，`equip` 是 `WeaponLoadout` 的左右手数组视图，战斗使用其去重后的武器实例列表。
- **阶段**：`phase = explore（牌局）| rest（层间修整）| over（结算）`，由 `_phase` 派生，`setPhase` 发 `phase:change` 事件。
- **行动方法**：`flip / pickUp / attack / waitTurn / armWeapon / selectHand / switchToEquip / usePotion / useBuff / useItem / applyItemToWeapon / discard / discardEquip / enterExit / enterNextFloor`；点击敌人直接调用 `attack`，操作栏沙漏调用 `waitTurn`，统一结算一个不改变牌局的完整回合；`armWeapon` 仅为旧命令兼容及装备管理选择。
- **层间 rest 状态机**：`rest = { step: 'reward'|'shop', rewards, hasShop, stock, mode, pending }`；`chooseReward / skipReward → _advanceRest`（有商店→shop，无商店→直接下一层）；商店购买/修理/出售统一走 `pending → confirmPending / cancelPending`。
- **回合与结算**：`_tickTurn` 开始一个消耗回合的玩家行动，通过 `EffectQueue` 先推进回合计数、冷却、回合技能和持续状态；随后结算玩家动作、目标反击、死亡/奖励与行动后效果，普通攻击最后在 `TURN_END` 调用 `_monsterAttackAll` 让其余存活敌人各攻击一次。攻击还拆出 `consumeWeaponDurability` 与 `resolveMonsterRetaliation`，普通攻击和连斩后续攻击通过参数组合复用；连斩后续攻击不重复调用全场威胁阶段。整理行囊、拾取、药水/buff 等自由动作不调用 `_tickTurn`。
- **怪物技能**：`data/monster-skills.js` 只保存技能定义，`rules/monster-skills.js` 的 `MonsterSkillEngine` 负责按触发时机、冷却和通用效果类型执行；`reveal / turn:start / attack:after / damaged` 分别接入翻牌、回合、怪物攻击和怪物受伤流程。
- **陷阱与范围动作**：`trap:before-trigger` 是陷阱效果前的拦截事件；`flippableCards`、`resolveRandomAttackSplash`、`convertMonsterToGold` 为可复用的查询/范围/击杀组合动作。
- **命令边界**：`dispatch(command)` 为 UI 和未来技能/事件提供统一命令入口；现有方法保留以兼容当前界面。
- **存档**：`_save / load / _serInst / _deserInst / _serRest / _deserRest`；当前 `SAVE_VERSION=17`，版本不符自动清档；玩家保存护甲值、主动技能选择和藏匿回合，陷阱牌保存 `triggered`；行囊保存为 `{ columns, rows, placements: [{ x, y, rotation, item }] }`，装备保存为 `{ handCount, placements }`；圣遗物保存本局收藏、激活栏和每个圣遗物的运行时状态；棋盘牌额外保存 `faction/entityKind/summoned/ai`、生命状态和 `skillState`；新局由 `STARTER_WEAPON_ID` 注入左手初始武器；读档后 `rest` 的 `pending/mode` 有意重置。
- **事件总线**：UI 使用 `makeEmitter`（on/off/emit）；规则层另有 `ruleBus` 和有序触发器注册表，结算完成后再通知外部观察者。

### 3.3 `src/game/core` / `src/game/model` / `src/game/rules` — 第一阶段规则内核

- `core/rng.js`：统一封装 JavaScript 随机数；当前不保存随机状态，未来可替换为带种子的实现。
- `core/commands.js`：统一行动命令名和 `command()` 工厂。
- `model/backpack.js`：提供 10×5 行囊、形状旋转、越界/重叠检查、首个可用位置搜索、移动和序列化。
- `model/containers.js`：提供通用线性容器；`model/loadout.js` 的 `WeaponLoadout` 负责单手/双手占位、替换、去重、序列化；双手武器内部占用左右手，但数组视图只在右手显示，左手由 `isUnavailable()` 标记不可用。
- `rules/combat.js`：武器攻击、耐久倍率、克制关系和暴击计算。
- `rules/modifiers.js`：按优先级/获得顺序结算数值修正；同一阶段的百分比修正相加。
- `rules/resolution.js`：按阶段、优先级、来源顺序执行同步效果队列，并记录结算轨迹。
- `rules/status.js`：独立计时、替换、刷新和取最大值等状态容器。
- `rules/triggers.js`：按能力注册顺序收集触发器，交给效果队列执行。
- `rules/monster-skills.js`：按牌面技能 id 收集怪物技能，执行冷却、状态、攻击、理智和移动效果。
- `rules/queries.js`：8 邻域和距离查询，供陷阱、技能和地图效果使用。
- `model/relics.js` + `rules/relics.js`：圣遗物本局收藏、5 栏激活、获得顺序、通用 hooks/modifiers/actions；具体效果不写入 `GameState` 分支。

### 3.4 `src/render/scene.js` — 3D 表现（读 state，不写状态）

- 竖屏相机（fov 58、俯视约 59°、距离 13.5）；`boardGroup` 含网格背景（可拖动平移），`cardsGroup` 为牌阵。
- 每张牌 = 一个 Group（背面/正面 Mesh + Canvas 纹理）；`_makeBackTexture` 绘制牌背（含污染裂纹 + ☣ 角标），`_makeFrontTexture` 按牌型绘制牌面（战利品加"点击拾取"黄条，出口加"点击进入 ▶"）。
- `_applyPhase`：rest 时隐藏牌阵、灯光压暗（只留网格背景）。
- 交互：`_pickCard` 射线拾取（跳过已生效牌）；`_handleClick` 翻牌/拾取/攻击/出口；渲染循环做出口激活脉冲高亮、战利品暖色呼吸。
- `isConsumed` 的牌（怪物已死、金币/钥匙已拾、战利品已捡）直接隐藏。

### 3.5 `src/ui/hud.js` + `hud.css` — 界面层

- 竖屏 flex 布局：状态栏(44px) → 情绪栏(26px，情绪左 + buff 提示右) → `#app` 场景(flex:1) → 装备栏 + 10×5 行囊。
- 行囊按物品形状和旋转角度渲染；点击物品选中、点击空格移动、旋转按钮改变朝向；`.card-actions` 浮层按钮（左下丢弃 / 中间主动技能 / 右下使用，仅 explore 阶段）。主动技能短按施放，长按打开图标选择列表；列表图标短按选择、长按打开技能说明。所有长按由 `long-press.js` 统一识别。
- 层间面板 `.hud-rest` 铺满场景区（无边框无背景不滚动）：奖励三卡 → 商店 4×2 货架 → 修理/出售（目标选择 + 确认栏）→ 跳过/进入下一层。
- 其他：日志浮层（含发送到 7700 服务）、设置（显示牌内容调试开关）、结算遮罩、阶段切换淡场。
- 渲染策略：监听 `state.on('change')` 全量重绘（数据量小，够用）。

## 4. 关键机制实现要点

| 机制 | 实现 |
|------|------|
| 翻牌邻域 | `isAdjacentToFlipped(card)` → `rules/queries.js`：与任意已翻开牌行列差 ≤1（8 邻域） |
| 污染 | 生成时按 `20%~30% + 环境加成` 随机标记（排除钥匙/出口/入口/陷阱）；翻开时按牌型结算；拾取时补写药水/道具/buff 污染负面标记 |
| 克制 / 耐久 | `rules/combat.js`：克制 1.3 / 被克制 0.7 / 正常 1.0；`durFactor`：≥7→1，4~6→0.8，1~3→0.6，0→0 |
| 情绪 | `rollEmotionId`：按 san 比例加权；每 5 回合在 `_tickTurn` 触发；效果经 `emotionDef()` 应用于攻/防/掉落/落空 |
| Boss | `_rotateBoss` 每回合轮换弱点；`monsterAttackValue` 内实现狂暴（hp<20 攻+2）；`_tickTurn` 内实现塔威（每 3 回合 -1 HP） |
| 怪物技能 | `MonsterSkillEngine` 按牌面技能 id 执行翻出即攻击、周期状态、攻击后理智损失和受伤移动；技能状态随牌面序列化 |
| 失控 | `madness` getter（san≤0）→ `_madnessAct` 随机行动后回 3 理智 |
| 点击拾取 | `flip` 只翻牌留场；`pickUp` 二次点击放入行囊（不耗回合，无适合形状时留场） |
| 道具直用 | `selectHand` 选中行囊道具自动置 `itemTargetMode`；`applyItemToWeapon(uid)` 直接作用于行囊/装备栏武器 |
| 层间转场 | `_advanceRest`：无商店层间选完/跳过奖励立即 `enterNextFloor` |
| 结算顺序 | `EffectQueue` 阶段：回合开始 → 伤害（按武器顺序）→ 耐久 → 目标反击一次 → 次级效果 → 死亡/行动后效果 → `TURN_END` 其余敌人各主动攻击一次 → 死亡检查 |
| 3D 牌面 | 150×170 Canvas 纹理（牌型短比例）；出口激活 emissive 绿色脉冲 + 抬升 |

## 5. 运行与联调

- **启动**：`cd three-vite-demo && npm run dev`（用户手动执行；`predev` 会尝试补防火墙规则，需管理员时用 `scripts/firewall-setup.bat`）。
- **访问**：本机 `http://localhost:3000`；局域网/Tailscale 用本机 IP（如 `http://100.x.x.x:3000`，需 3000 入站放行）。
- **日志联调**：`node scripts/log-server.mjs` 启动 7700 服务，HUD 日志面板"发送日志"会把最近日志 POST 过去。
- **构建**：`npm run build` → `dist/`。
- **规则检查**：`npm run check:rules` → 第一阶段规则内核、单手/双手占位和双持攻击流程的快速断言。
- **逻辑自测**：`scripts/phase1-check.mjs`、`phase2-check.mjs`、`phase3-check.mjs` 覆盖规则内核、双手装备和行囊形状/旋转；命令为 `npm run check:rules`。
