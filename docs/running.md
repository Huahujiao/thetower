# 运行游戏

首次使用或依赖缺失时先运行 `npm install`。日常游玩运行 `npm start`，打开 http://localhost:4173（美术残局为 `/arttweak`）。第一次启动会先生成资源并构建，之后保持服务运行即可。手机使用同一局域网中的电脑地址和 4173 端口。

该入口使用打包后的页面，不包含开发热更新客户端，因此开发连接断开、恢复或切换标签页不会触发 Vite 自动重载。构建产物中带内容哈希的脚本、样式和图片缓存一年；内容变化时文件地址随之变化。HTML 保持重新校验，避免入口长期停留在旧版本。

修改代码后重新运行 `npm start` 更新构建；已有构建直接运行 `npm run preview`，不用再次构建。开发或手机美术调试运行 `npm run dev`，地址为 http://localhost:3000。默认关闭热更新、开发 WebSocket 与客户端连接，手机切到后台导致连接断开时不会进入 Vite 的重连整页刷新；源文件仍由 Vite 按需转换，修改代码后手动刷新即可。需要即时热更新时使用 `npm run dev:hmr`，这个入口保留 Vite 原有的重连刷新行为。

从旧配置更新后，Vite 会重新启动服务；已经打开的页面仍持有旧客户端，需要手动刷新一次。Tailscale 使用同一台电脑的 Tailscale IP 和对应端口，不要求为这项修复更换网络。

资源缓存与进度存档独立：正常游戏沿用已有自动存档；`/arttweak` 是固定美术残局，每次真正重新加载都会重新创建场景。浏览器主动回收标签页仍可能导致重新加载，不由网站缓存策略控制。

`npm run check:dev-session` 检查默认开发模式没有连接/恢复轮询/自动刷新，验证 Vue 与 CSS 加载及可选热更新模式；`npm run check:runtime-cache` 检查打包入口的 HTTP 缓存。开发源码的 `no-cache` 表示重新校验，不能据此判断每次都重新下载完整资源；是否重新创建场景首先取决于页面是否真的重载。
